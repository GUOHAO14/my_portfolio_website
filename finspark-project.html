Finspark Administration Website

A centralized Node.js & Express.js web application designed to streamline business operations for Finspark Sdn Bhd (Finspark Holdings and MMC FP Sdn Bhd). Integrates with AutomaticSales.ai (CRM) and AutoCount Cloud Accounting (accounting software) for comprehensive management of courses, payments, and financial documents.

Project Overview

As part of my 12-week internship at Finspark Sdn Bhd, I led the research, design, and development of a comprehensive administration website. The project addresses critical workflow inefficiencies across multiple departments by consolidating course management, customer relationship management, and financial operations into a single, intuitive platform. The centralized system also aims to resolve the company's problem of data fragmentation, where user and business data were spread across different platforms.

Due Finspark's nature of being an SME with less focus in IT operations, I had to develop the system by myself with occasional supervision from my supervisors. The alpha version was officially deployed to live production in October 2025 and used by 15+ employees across finance, operations, marketing, and sales departments.

Architecture & Key Systems

1. Authentication & Authorization

Multi-layer authentication using JWT tokens and Google Sheets* as the user database. Role-based access control with granular permission caching for performance optimization. Features include session management, secure cookies, and fallback authentication using admin credentials.

Google Sheets was utilized as a lightweight database solution to balance functionality and cost-efficiency. Due to the company's relatively small operational scale, deploying a full-scale database management system was not considered necessary. This approach is subject to change as future scalability requirements evolve.

2. Course Management System

Kanban-style interface for managing course schedules. Supports both online and offline courses. This feature allows admins to view students who are scheduled to attend a course for a particular date. Drag-and-drop functionality allows admins to reallocate students between course dates. Color-coded payment status indicators provide at-a-glance visibility into customer payment progress.

3. AutoCount Integration

Seamless integration with AutoCount Cloud Accounting API for managing debtors (companies), quotations, and other financial documents. Quotation capacity management ensures registration slots are accurately tracked. All financial transactions are automatically recorded and categorized.

4. Payment Verification Workflow

Three-stage payment approval process: submission (via payment forms) → pending review (stored in Google Sheets) → approval/rejection by finance team. Once approved, Official Receipts or Payment Vouchers are automatically created in AutoCount, while its details will be pulled to the system for viewing. Rejected payments are logged for audit purposes.

5. Document Generation Pipeline

Uses DocxTemplater to populate Word templates with customer data, then converts to PDF via LibreOffice. Supports quotations, invoices, official receipts, and payment vouchers. All documents are versioned and stored for audit trail purposes.

Technical Highlights

API Integration Strategy

Built custom service classes to abstract complex API interactions with AutomaticSales.ai and AutoCount. Implemented error handling, retry logic, and rate limiting to ensure reliable integration with external services.

Security Implementation

Multi-layer security stack including CORS configuration, express rate limiting, input sanitization, XSS protection headers, and secure JWT authentication. Environment variables (stored in .env file and Heroku) protect sensitive credentials and API keys.

Containerization with Docker

Implemented Docker containerization for consistent development and production environments. Dockerfile includes LibreOffice dependencies for PDF generation capabilities. Multi-stage builds optimize image size and caching efficiency.

Performance Optimization

Permission caching reduces database queries for frequently accessed role permissions. Batch email processing with rate limiting prevents service throttling. Strategic use of async/await for non-blocking I/O operations.

Deployment & Maintenance

Deployment Strategy: Automated CI/CD pipeline using GitHub Actions. Commits trigger Docker image builds that are pushed to Heroku's container registry. Application redeploys automatically within ~3 minutes.

Local Development: Standard Node.js setup with .env configuration. Docker support available for testing PDF generation features with LibreOffice dependencies. Comprehensive .gitignore protects sensitive files.

Future Improvements: The codebase includes detailed documentation for successors. Some areas flagged for refactoring include quotation API consistency and expanded test coverage.
